## Per-skill catalogue

### `improve-ui` — `skills/improve-ui/SKILL.md`

Contract-gated audit of one coherent product surface: traces the rendered path through routes/layouts/compositions, reconstructs the governing design system from `DESIGN.md` and local docs, then admits a finding only when three proofs exist — a binding contract, a runtime path to the surface, and a single deterministic correction. Strictly read-only on product source; writes self-contained remediation plans under `design-plans/` for another agent to execute; caps output at 3 findings and explicitly discards functional/a11y/metadata findings unless requested. Install: `npx skills add ibelick/ui-skills@improve-ui -g -y`. `composable: false` (it is an audit that produces plans, not a fix lane).

### `baseline-ui` — `skills/baseline-ui/SKILL.md`

Fast deslop baseline expressed as MUST/SHOULD/NEVER rules across stack (Tailwind defaults, `motion/react`, `cn`), components (accessible primitives — Base UI/React Aria/Radix), interaction (`AlertDialog` for destructive actions, `h-dvh` not `h-screen`, safe-area), animation (compositor props only, ≤200ms feedback, `prefers-reduced-motion`), typography (`text-balance`/`text-pretty`/`tabular-nums`, never touch tracking), layout (fixed z-index scale, `size-*`), performance (no `blur()`/`will-change` abuse), and design (no gradients/purple/glow, one accent, real empty states). Usable as `/baseline-ui` whole-conversation pass or `/baseline-ui <file>` violation report. Install: `npx skills add ibelick/ui-skills@baseline-ui -g -y`. `composable: true`.

### `fixing-accessibility` — `skills/fixing-accessibility/SKILL.md`

a11y audit-and-fix lane with 9 prioritized rule categories: accessible names, keyboard access, focus/dialogs (critical); semantics, forms/errors (high); announcements (medium-high); contrast/states (medium); media/motion (low-medium); tool boundaries (critical — what NOT to claim fixed). Ships a common-fixes section and review guidance for verification. Install: `npx skills add ibelick/ui-skills@fixing-accessibility -g -y`. `composable: true`.

### `fixing-motion-performance` — `skills/fixing-motion-performance/SKILL.md`

Motion/rendering-performance audit-and-fix lane, 9 prioritized categories: never-patterns and mechanism choice (critical — compositor `transform`/`opacity` vs paint vs layout; choose CSS/WAAPI/FLIP/scroll-timeline correctly), measurement and scroll (high), paint/layers/blur-filters (medium), view transitions (low), tool boundaries (critical). Includes a rendering-steps glossary so findings cite the actual pipeline stage. Install: `npx skills add ibelick/ui-skills@fixing-motion-performance -g -y`. `composable: true`.

### `fixing-metadata` — `skills/fixing-metadata/SKILL.md`

Metadata/SEO audit-and-fix lane, 8 prioritized categories: correctness/duplication (critical), title/description, canonical/indexing, social cards — OG/Twitter (high), icons/manifest, JSON-LD structured data (medium), locale/alternates (low-medium), tool boundaries (critical). Web-only surface (HTML `<head>`/SEO has no mobile analog in this registry's sense). Install: `npx skills add ibelick/ui-skills@fixing-metadata -g -y`. `composable: true`.

### `create-design-md` — `skills/create-design-md/SKILL.md`

Standalone `DESIGN.md` reconstruction, two modes: repository mode (trace tokens/components/patterns from source evidence) and URL mode (reconstruct from a public site). Shared evidence pipeline: trace → decide what belongs → write → validate (`npx @google/design.md lint|export`) → report. Read-only on product source; refuses to promote accidental implementation patterns into design decisions. This is the kit's no-impeccable fallback for DESIGN.md drift (impeccable's `document`/`extract` covers that tier only when installed). Install: `npx skills add ibelick/ui-skills@create-design-md -g -y`. `composable: false` (document generation, not a per-finding fix lane).

### Surface correction (review r1)

The card's draft table proposed `surface: both` for all six rows. Verified against upstream rule content: `baseline-ui` rules are Tailwind/CSS-specific (`h-dvh`, `tw-animate-css`, `text-balance`), `fixing-accessibility` is HTML/ARIA-only ("audit and fix HTML accessibility issues"), and `fixing-motion-performance` is DOM-rendering-specific (CSS/WAAPI, compositor pipeline, scroll timelines). All three are catalogued as `surface: web` — routing them to native-mobile tasks would dispatch inapplicable rules. `improve-ui` stays `both` (source-level tracing of routes/layouts/compositions is stack-agnostic — it audits whatever the repo's surface technology is) and `create-design-md` stays `both` (repository mode reads any codebase; URL mode is web-input but the output applies wherever DESIGN.md governs). `fixing-metadata` was already `web`.

## Non-adoption: `ui-skills-root`

`ui-skills-root` exists in the repo (`skills/ui-skills-root/SKILL.md`, listed in both CLIs) but is **not catalogued**. Its own description — "Use before UI-related work to select the smallest useful UI Skills context through the ui-skills CLI" — is a *router*: it exists to pick which ui-skills to load for a task. The kit already has that layer: `ui-design-orchestrator`'s SKILL.md + REGISTRY.md is the routing engine, and adding a second router would create competing route tables and dual truth for "which skill applies when" (binding decision D8 of the PRD). The six leaf skills are adopted as *data rows* in our router instead.

## Acknowledged gaps NOT fixed by this absorption

1. **No upstream anti-default gate.** The ui-skills set audits/fixes against contracts and baselines but has no "don't produce LLM-default design" discipline at intake — `baseline-ui` forbids purple gradients and glow *in code*, but nothing upstream stops a generic direction from being chosen. Covered by the kit's existing layer: `prompts/brief.md:88-95` "Anti-default discipline" + impeccable's `shape`/new-work flow when installed (188 visual-world challengers).
2. **No rendered-browser evidence.** `improve-ui` accepts rendered evidence only when the user provides it, and none of the fix lanes verify in a live browser — findings are source-level. Covered by the kit's `verify` tier: `browser-testing-with-devtools` (mandatory responsive verification, REGISTRY.md `verify` row) plus `npx impeccable detect` when installed.

## Recommendation

`adopt-component` — land the six leaf skills as `audit-fix` routing data (all `required: false`, fix lanes `composable: true`, `improve-ui`/`create-design-md` `composable: false`); skip `ui-skills-root`. T2 (`modes/audit-fix.md`) defines the finding-type routing + fix-loop contract that dispatches these lanes.
